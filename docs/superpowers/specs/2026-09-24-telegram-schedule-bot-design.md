# Дизайн Telegram-бота расписания колледжа

## Цель и границы

Добавить к существующему веб-сервису Telegram-бота, который читает те же таблицы Supabase, запоминает выбранную группу пользователя и отвечает на два основных запроса: расписание на сегодня и состояние занятий сейчас.

Первая версия работает только в личных чатах. В неё не входят групповые чаты, расписание на произвольный день, автоматические уведомления, административные команды и редактирование данных. Расписание продолжает редактироваться через Supabase Dashboard, а статический сайт сохраняет существующую архитектуру и способ развёртывания.

## Платформа

Бот реализуется как Supabase Edge Function на TypeScript и получает обновления через Telegram webhook. Это размещает вычисления рядом с единой базой данных, не добавляет отдельный постоянно работающий сервер и не превращает статический сайт в серверное приложение.

Endpoint функции доступен без Supabase JWT, потому что Telegram не может передавать пользовательский Supabase-токен. Подлинность каждого webhook-запроса проверяется по заголовку `X-Telegram-Bot-Api-Secret-Token`, значение которого задаётся при регистрации webhook.

Официальные справочные материалы:

- https://supabase.com/docs/guides/functions
- https://supabase.com/docs/guides/functions/deploy
- https://supabase.com/docs/guides/functions/secrets
- https://core.telegram.org/bots/features#creating-a-new-bot
- https://core.telegram.org/bots/api#setwebhook

## Файловая структура

Новые серверные файлы располагаются отдельно от статического сайта:

- `supabase/config.toml` — отключает Supabase JWT-проверку только для `telegram-bot`.
- `supabase/functions/telegram-bot/index.ts` — HTTP-обработчик webhook и маршрутизация Telegram updates.
- `supabase/functions/telegram-bot/bot.ts` — команды, callback-действия и построение ответов.
- `supabase/functions/telegram-bot/schedule.ts` — чистая логика времени, выбор состояния занятий и форматирование.
- `supabase/functions/telegram-bot/telegram.ts` — минимальный клиент Telegram Bot API.
- `supabase/functions/telegram-bot/types.ts` — используемые типы Telegram и записей Supabase.
- `supabase/functions/telegram-bot/*.test.ts` — Deno-тесты чистой логики и обработчиков.

Существующий `database.sql` расширяется закрытой таблицей пользовательских настроек. `README.md` получает инструкции по созданию бота, secrets, deploy и webhook.

## База данных

Добавляется таблица `public.telegram_users`:

- `telegram_user_id bigint primary key` — стабильный идентификатор Telegram-пользователя;
- `chat_id bigint not null` — идентификатор личного чата для ответа;
- `group_id bigint not null references public.groups(id) on delete cascade`;
- `created_at timestamptz not null default now()`;
- `updated_at timestamptz not null default now()`.

Для `group_id` создаётся индекс. На таблице включается RLS, но политики для `anon` и `authenticated` не создаются. Доступ к пользовательским настройкам имеет только серверный контекст Edge Function. Сохранение группы выполняется через `upsert` по `telegram_user_id`, поэтому повторная доставка одного callback не создаёт дубликаты.

## Пользовательский сценарий

### Первый запуск

Пользователь отправляет `/start`. Бот принимает команду только из личного чата и ищет сохранённую настройку. Если группы нет, бот получает список `groups` и показывает inline-клавиатуру. Каждая callback-кнопка содержит компактное значение `group:<id>`.

После выбора бот повторно проверяет существование группы, сохраняет `telegram_user_id`, `chat_id` и `group_id`, закрывает индикатор callback и отправляет главное меню.

### Главное меню

Reply-клавиатура содержит:

- `Сегодня`;
- `Сейчас`;
- `Изменить группу`.

Поддерживаются команды `/today`, `/now`, `/group` и `/help`. `/start` для уже настроенного пользователя показывает текущую группу и главное меню. `/group` и кнопка «Изменить группу» повторно открывают inline-выбор; следующий выбор заменяет предыдущий. Неизвестный текст возвращает краткую подсказку и главное меню.

### Сегодня

Бот определяет календарный день в фиксированном часовом поясе `Asia/Almaty`. Для воскресенья сразу возвращается сообщение об отсутствии занятий. В остальные дни расписание фильтруется по сохранённому `group_id` и `day_of_week`, сортируется по `lesson_number` и отправляется одним компактным текстовым сообщением.

Каждая строка содержит номер пары, предмет и время `HH:MM — HH:MM`. Если строк нет, бот отвечает «На сегодня занятий нет».

### Сейчас

Текущее время вычисляется в `Asia/Almaty`, а интервалы расписания переводятся в минуты. Границы начала и окончания входят в текущую пару. Возможные ответы:

- идёт пара — номер, предмет и интервал;
- перемена — следующая пара и время начала;
- занятия ещё не начались — первая пара и время начала;
- занятия закончились — завершение учебного дня;
- расписание пусто — на сегодня занятий нет.

## Обработка webhook

Функция:

1. Отвечает `405` на методы, отличные от `POST`.
2. Сравнивает webhook-secret без вывода значения в логи и отвечает `401` при несовпадении.
3. Безопасно разбирает JSON и отвечает `400` на некорректное тело.
4. Принимает только обновления `message` и `callback_query`.
5. Игнорирует чаты, у которых `chat.type` не равен `private`.
6. Маршрутизирует команду, текст кнопки или callback.
7. Возвращает Telegram статус `200` после корректно обработанного либо намеренно проигнорированного update.

При внутренних ошибках пользователю отправляется нейтральное сообщение «Не удалось загрузить расписание. Попробуйте позже», а в журнал записываются только безопасное описание и тип операции. Токен, webhook-secret, тексты пользовательских сообщений и Telegram-идентификаторы не логируются.

## Секреты и доступ

В Supabase Edge Function Secrets задаются:

- `TELEGRAM_BOT_TOKEN` — токен, выданный BotFather;
- `TELEGRAM_WEBHOOK_SECRET` — случайное значение длиной не менее 32 символов из букв, цифр, `_` и `-`.

Токен не сохраняется в `.env` внутри репозитория, не вставляется в `config.js`, не передаётся сайту и не коммитится. Edge Function использует серверный ключ Supabase только внутри управляемого runtime для чтения расписания и записи `telegram_users`.

## Создание и развёртывание

1. В официальном `@BotFather` выполнить `/newbot`, задать отображаемое имя и уникальный username длиной 5–32 символа с окончанием `bot`.
2. Сохранить полученный токен непосредственно в Supabase Edge Function Secrets.
3. Выполнить обновлённый `database.sql`.
4. Установить Supabase CLI, авторизоваться, связать проект по reference `gchgtvcklerhlfmwmica` и развернуть `telegram-bot`.
5. Зарегистрировать URL `https://gchgtvcklerhlfmwmica.supabase.co/functions/v1/telegram-bot` через Telegram `setWebhook`, передав тот же `secret_token` и ограничив `allowed_updates` значениями `message` и `callback_query`.
6. Проверить `getWebhookInfo`: URL заполнен, `pending_update_count` не растёт, последняя ошибка отсутствует.
7. Открыть личный чат с ботом и выполнить `/start`.

Если CLI-аутентификация или BotFather требуют действий владельца, разработка локальных файлов продолжается, а финальный deploy выполняется после предоставления соответствующего доступа вне репозитория.

## Тестирование

Чистые функции проверяются Deno-тестами без сетевых запросов. Тесты покрывают:

- преобразование времени и все состояния «Сейчас»;
- определение дня и минут в `Asia/Almaty` на фиксированных датах;
- форматирование расписания и пустого дня;
- маршрутизацию `/start`, `/today`, `/now`, `/group`, `/help` и кнопок меню;
- строгий разбор `group:<id>`;
- отказ при неправильном webhook-secret;
- `405` для неподдерживаемого метода и `400` для некорректного JSON;
- игнорирование групповых чатов;
- повторный выбор группы через upsert;
- безопасное пользовательское сообщение при ошибке базы или Telegram API.

После deploy выполняется интеграционная проверка `getWebhookInfo`, `/start`, первоначального выбора группы, обоих действий, смены группы и повторного запуска.

## Критерии готовности

Пользователь может создать личный чат с ботом, выбрать существующую группу, вернуться позже без повторного выбора, открыть расписание на сегодня, проверить текущую пару и в любой момент изменить группу. Бот и сайт читают единые данные Supabase. Секреты отсутствуют в Git, webhook проверяет источник запроса, таблица привязок недоступна публичным клиентам, автоматические и интеграционные проверки проходят.
