# Date-Based Monthly Schedule Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Store and display concrete-date schedules for both groups throughout September 2026 on the website and in the Telegram bot.

**Architecture:** `public.schedule` remains the single source of truth, but replaces weekday recurrence with a `lesson_date` key. Browser code queries the user's local ISO date; the bot derives the ISO date and display label in `Asia/Almaty`, then passes that date through the repository boundary.

**Tech Stack:** PostgreSQL/Supabase, Vanilla JavaScript, Supabase Edge Functions with TypeScript, Node.js test runner.

## Global Constraints

- Seed dates cover `2026-09-01` through `2026-09-30` inclusive.
- Sundays have no lessons; Monday through Saturday have seeded demo lessons for both groups.
- Dates are transferred as `YYYY-MM-DD` strings without UTC conversion.
- Existing `groups`, `telegram_users`, RLS policies, and saved Telegram group choices remain intact.
- Re-running `database.sql` must not create duplicate schedule rows.
